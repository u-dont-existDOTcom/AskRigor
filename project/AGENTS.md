# `project/` Agent Instructions

- Treat project status/checkpoint files as routing documents, not substitutes for the complete canonical protocols or exact repository evidence.
- Before trusting a checkpoint, inspect current Git state, canonical protocol files, current status/update-check records, and newer owner instructions; repair stale entries immediately.
- Record goal, protocol/version baseline, active owner constraints, completed work not to repeat, current step, last verified durable boundary, remaining work, blockers, evidence/tests/commits, and next safe action.
- Never store credentials, secret values, private health data, private chain-of-thought, or large raw logs here.
- Distinguish verified protocol/application facts from planned work, remembered summaries, and unverified hosted GitHub controls.
- A checkpoint never outranks current complete `HRP_Full.xml`, `Universal_Instructions.xml`, explicit owner correction, tests, or exact source evidence.
- After interruption or a fresh thread, identify exactly what survived and resume from the latest verified durable boundary without repeating completed work.
