# Security Policy

## Supported version

Security fixes target the current `main` branch and the currently documented
production release. Candidate and production state remain distinct in
`docs/release-evidence-v0.1.0.md`.

## Report a vulnerability privately

Email `joel@askrigor.com` with the subject `AskRigor security report`. Include
the affected route, version or commit when known, impact, and the smallest safe
reproduction. Do not open a public issue for an undisclosed vulnerability. Do
not send API keys, credentials, private health information, exploit payloads,
or unnecessary personal data.

GitHub private vulnerability reporting was verified enabled through the
repository API on 2026-08-15. The Security-tab flow is preferred; email remains
an authenticated fallback when the hosted form cannot be used.

AskRigor is not an emergency or medical-advice service. For an urgent medical
concern, contact local emergency services or a qualified professional.

## Response boundary

The maintainer will acknowledge a reproducible report when practical, preserve
confidentiality during remediation, and coordinate disclosure after a fix or
documented risk decision. No response-time or bounty commitment is implied.
