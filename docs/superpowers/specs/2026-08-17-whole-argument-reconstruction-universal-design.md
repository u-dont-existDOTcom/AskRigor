# Whole-Argument Reconstruction Universal Integration Design

**Status:** Owner-directed immediate integration

## Objective

Promote the already accepted domain-general whole-argument reconstruction control into AskRigor's complete canonical `protocols/Universal_Instructions.xml` without changing the HRP, weakening the existing premise-integrity gate, or leaving protocol identity records stale.

## Authority and boundary

- Current owner instruction controls the requested change.
- The exact `main` bytes of `protocols/Universal_Instructions.xml` version `20.5.12`, revision `2026-08-16`, are the only permitted base.
- The reusable source is `u-dont-existDOTcom/universal-dev-architecture/patterns/whole-argument-reconstruction.md` at merged `main` commit `015db68c522454b907feed21a84afc4c8364b406`.
- Romance-specific prose, people, accusations, and examples remain outside AskRigor's universal protocol.
- `protocols/HRP_Full.xml` is unchanged. When HRP applies, its own stricter research architecture continues to control.

## Canonical protocol change

Bump Universal to version `20.5.13`, revision date `2026-08-17`, and add:

1. A revision-history entry describing the new gate.
2. A dedicated `<whole_argument_reconstruction_gate priority="Critical">`.
3. A point-of-generation check.
4. Exact manifest/test/state updates derived from the resulting bytes.

The gate requires a worker, before criticizing, fact-checking, summarizing, editing, or transforming a substantial source, to:

- recover the complete current source and architecture when available;
- quote the exact disputed passage and trace its definitions, qualifications, examples, exceptions, and callbacks;
- preserve subject, action, operative object, chronology, modality, scope, evidence status, and concessions;
- state the complete reconstructed claim before evaluation;
- classify the defect precisely, including `no defect` when the objection disappears;
- distinguish a true behavior label from a fuller contextual explanation;
- distinguish missing content from late setup, unclear primary home, or weak transition;
- preserve unaddressed proposals after selective feedback and use silence-as-approval only when the owner established that bounded convention;
- provide an exact repair contract for substantive changes;
- run a whole-source verification before completion.

## Integration mechanism

Use a one-off guarded Node updater on a dedicated task branch. It must fail unless the exact expected base version/date and insertion markers occur once. It updates canonical XML, protocol tests, current byte receipts, and any exact current-manifest references transactionally, then computes the new SHA-256. A temporary branch-only workflow runs `npm ci`, the updater, `npm run verify`, and `git diff --check`, then commits the generated files. Remove the updater/workflow before merge.

## Verification

- Red: a new structural regression fails against Universal `20.5.12` because the gate is absent.
- Green: the structural regression and full `npm run verify` pass after generation.
- Inspect the final PR diff for exact scope.
- Merge only the exact CI-green head.
- Confirm merged `main` exposes Universal `20.5.13` and the new canonical SHA-256.

## Non-goals

- No HRP version change.
- No application, API, public-site, provider, privacy, or deployment change.
- No attempt to encode project-specific memoir conventions into a universal protocol.
- No claim that repository persistence is equivalent to ChatGPT profile-memory storage.
