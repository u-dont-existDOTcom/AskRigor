## What the owner decided

An error log on the research MCP server (`apps/research-mcp`) so faults can be found and fixed. AskRigor keeps no
request logs today by design; the privacy page says so. The owner chose:
- 432 1b: the log also keeps the search words of FAILED calls (not of slow successful calls);
- 433a: those words are kept only for accounts with the switch "keep my failed searches" on; the owner's own accounts
  are on from the start; every other failed call keeps only the search's SHAPE.
(He may yet ask for the switch to be on by default for everyone with an opt-out: make the default ONE server setting,
default off, so that change is a single value; do not build the opt-out default.)

## Exactly what the log keeps (nothing else)

For every research tool call that ends in an error (its final outcome: a source timing out before a working fallback is
not a failed call), and every call that takes more than 10 seconds even when it succeeds:
- time (UTC ISO), duration in ms, tool name, outcome (`error` | `slow`);
- the app that sent it if the server already knows it (chatgpt | claude | gemini | other | unknown), from whatever the
  server already records about the client; do not add new client fingerprinting;
- public paper identifiers involved (PMID, PMCID, DOI), validated by format, taken only from the call's arguments or the
  failing source's identifiers;
- for a failed call: the kind of error and where, from a FIXED list you define (for example `source_timeout` +
  `europe_pmc`, `source_http_error` + `pubmed` + status class, `rate_limited`, `validation_error`, `auth_refused`,
  `internal_error`), never raw exception or error text (it can carry queries, links or IDs);
- for a failed call: the search's SHAPE: which argument fields were filled, the word count of each free-text field, and
  values of enumerated or numeric options (never free text);
- for a failed call from an account whose switch is on: the free-text search words, after removing email addresses,
  phone numbers, IP addresses, URLs and long digit runs (reuse AskRigor's existing privacy screen if there is one; if
  the screen fails, drop the words). Never keep words for YouTube tools, for any tool that may send the words to
  YouTube, or when the call's destination is not known.

Never: account, user, session or request IDs, IP or network addresses, credentials, tokens, headers, URLs, tool
results, answers, text from sources, raw errors. The switch lookup may use the account inside the request, but the
entry must not store it.
