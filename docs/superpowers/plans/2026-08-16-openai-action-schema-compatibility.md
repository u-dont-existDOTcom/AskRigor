# OpenAI Action Schema Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make AskRigor's generated Action schema pass the three OpenAI editor checks reported by the owner without changing MCP behavior.

**Architecture:** Keep compatibility logic at the Action export boundary. Emit the importer-required `components.schemas` object, author concise legacy YouTube Action descriptions, and enforce the editor's 300-character ceiling in deterministic tests.

**Tech Stack:** TypeScript, Zod-generated JSON Schema, Vitest, deterministic OpenAPI generation, GitHub Actions, Docker Compose production release.

## Global Constraints

- Preserve all canonical protocol bytes and the frozen 17-tool MCP inventory.
- Preserve request schemas, response schemas, operation IDs, provider behavior, privacy boundaries, and consequential-operation classification.
- Do not truncate descriptions generically or shorten the shared MCP descriptions.
- Keep every exported Action operation summary and description at most 300 characters.
- Keep Custom GPT Knowledge empty and leave the GPT unpublished until live editor acceptance.
