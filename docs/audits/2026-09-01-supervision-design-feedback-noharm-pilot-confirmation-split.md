# SUPERVISION_DESIGN_FEEDBACK — NOHARM pilot/confirmation split

Routing receipt: [AskRigor issue #174](https://github.com/u-dont-existDOTcom/AskRigor/issues/174).

## Observation

The AskRigor MAST plan allows a NOHARM pilot to estimate judge stability, cost, latency, severity distribution, and plausible decision margins, then freezes the complete-run analysis. The earlier plan also called the later all-30-family open epoch the complete evaluation.

If the pilot families influence the numerical margins or decision rules and are then included in the primary confirmation statistic, development data partly confirm choices they helped create.

## Implemented nonblocking repair

- Select ten pilot families outcome-blind: one of three cases from each specialty prefix by a pinned SHA-256 rule, retaining all eleven variants.
- Reserve the other twenty families as untouched `VALIDATION_CONFIRMATION` and explicitly label that set a partial corpus.
- Continue reporting the official all-30-family open-corpus score, but label it `DESCRIPTIVE_OFFICIAL_FULL_OPEN_CORPUS` rather than untouched confirmation.
- Do not repair HRP from pilot cases.
- Hash-seal the analysis freeze after the pilot and before any untouched-family result is observed.

This keeps every available case in evidence review and preserves official benchmark reporting. It changes only the inferential role assigned to cases used for development.
