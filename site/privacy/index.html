Privacy Notice

Scope

This notice describes AskRigor’s v0 research retrieval path and its separately configured, optional lesson-feedback path. Research operations remain read-only and do not modify provider records. Short-lived Custom GPT continuations for YouTube and identity-verified open publications are the only research state retained across application requests.

Connected research transports

The public MCP service and Custom GPT Actions use the same transient research retrieval path and shared abuse limits; Custom GPT-only reads can additionally retrieve public YouTube caption text, public open-publication text, and a Gemini-assisted public YouTube candidate frontier. The research Action transport is independently gated by ASKRIGOR_RESEARCH_ACTIONS_ENABLED, limits each serialized response to 60,000 UTF-8 bytes, returns no more than 48,000 UTF-8 bytes of exact protocol text per ordered chunk, and returns bounded ordered publication segments. Requests may contain user search terms and public identifiers; responses may contain public provider metadata, comment text, and caption segments, as well as open publication text and provisional public-video discovery annotations. The application does not log full request or response bodies or write them to durable storage. Infrastructure, connected clients, and research providers may process operational or request data under their separately controlled policies. This does not change the separately consented lesson-feedback path described below.

Information processed

During an active request, the service processes supplied queries and identifiers, provider responses, normalized source metadata, pagination and access information, and structured errors needed for retrieval and provenance. For a requested DOI it may also process a public article’s source URL, title, manuscript version, format, exact document and block hashes, extracted JATS or PDF text, section or page location, and a source-linked study or review audit. For automated candidate discovery, AskRigor accepts only a deterministically screened, de-identified population-level research target and a diagnosis-status category; it rejects first-person, identifier-bearing, secret-like, URL-bearing, or instruction-like target text before credentials, budget, or provider access.

Public YouTube data

When a connected client requests it, AskRigor processes API-visible public YouTube author/channel IDs, optional display names, comment and reply text, comment and reply IDs, timestamps, and counts. The Custom GPT transcript read may also process public caption text, segment timing, available caption languages, and whether YouTube identifies the selected track as automatically generated. These data can be personal data even when public. Caption retrieval uses a best-effort unofficial YouTube interface and can fail even when captions appear in a browser. The service does not claim access to private, deleted, moderated, hidden, held-for-review, unavailable, or never-posted material, and it does not independently verify caption accuracy.

Why and where data is processed

AskRigor sends the query or identifier necessary for a request to public-data providers: NCBI/PubMed, Europe PMC, Unpaywall, ClinicalTrials.gov, Crossref, YouTube Data API v3, and—for the Custom GPT transcript read—the public YouTube website and Innertube interface. For automated YouTube candidate discovery, Google Gemini first receives only the screened population-level target and AskRigor’s public scout instructions, and Google Search runs inside that provider request. If Gemini’s compact public candidate packet does not pass strict server validation, AskRigor may make one no-search correction request to the same model containing only that public packet, the exact executed public searches, and bounded non-sensitive validation issues. Candidate public video IDs are then sent to YouTube for independent identity validation. Gemini summaries are only discovery annotations: they are not transcript verification or evidence that a treatment works. A public publisher or repository selected through Unpaywall may receive a bounded document request. Unpaywall receives a public service contact email. Providers process requests under their own policies.

Optional lesson feedback

After AskRigor rechecks a concrete criticism, it may display a generalized lesson and ask for separate consent to submit it. This optional, consequential Action sends AskRigor only generalized structured fields, not the raw chat, and creates a private review candidate. It is not automatic learning and cannot change AskRigor without human review.

Screening and recipients

AskRigor applies deterministic screening and a fixed OpenAI privacy check before GitHub, then screens the result again. OpenAI receives only the already generalized candidate fields. If every check passes, GitHub receives the accepted lesson fields, a privacy marker, and anonymous occurrence metadata for private review. ChatGPT handles the surrounding conversation under its own settings and terms.

Storage and retention

Direct MCP continuation remains client-carried and stateless. Gemini candidate discovery sets provider interaction storage to disabled; AskRigor does not retain the provider interaction ID, target, candidate packet, or provisional summaries after the active response. Google still processes the request under the configured API project’s terms. Transcript pages re-fetch the selected public caption track; no transcript text is retained between requests. Custom GPT YouTube continuations use short unguessable handles backed by bounded process-memory state for no longer than one hour. The comment-audit map stores a signed minimized token containing a video identifier, provider cursor, counters, bounded comment/reply identifiers, and a rolling digest; it stores no comment/reply or caption text, author identity, provider credential, or protocol text and is limited to 2,048 handles and 16 MiB. The transcript map stores only provider cursor, public video ID, selected-track metadata, caption-snapshot hash, page and segment counters, next expected segment index, and timestamp-presence state; it stores no caption text, title, channel name, request text, credential, or protocol text and is limited to 2,048 handles and 4 MiB. Neither map is written to disk or application logs. Server restart, expiry, or capacity eviction invalidates the handle and requires that video chain to restart. The separate open-publication map stores one exact identity-verified public document index and its next cursor, including extracted public text, public source metadata, manuscript version, section/page locations, and hashes; it is limited to 64 handles and 128 MiB total and contains no private publication copy, provider credential, or user health record. It also is never written to disk or application logs, and expiry, eviction, or restart requires the document chain to restart. This process-local design runs on a single application replica and must not be horizontally scaled unless approved sticky routing or shared state preserves every continuation chain. Apart from these bounded in-memory exceptions, AskRigor does not persist user accounts, search history, retrieved records, public captions, comments, replies, publications, Gemini candidate packets, or credentials. For optional lesson feedback, the private review candidate stores the accepted generalized fields, an anonymous occurrence count, first/last seen times, and a deduplication marker. No user account, conversation ID, medical history, upload, or raw quotation is intentionally stored. Rejected or incorporated candidates become deletion-eligible only after more than 90 complete days from terminal review. Deletion is not automatic; a maintainer must act, so it may occur later.

Operational metadata

The application does not emit or store request-body logs, response-body logs, candidate-content logs, or a dedicated application access log. In routine operation it emits only a startup line. A disabled-by-default connector diagnostic may temporarily emit fixed non-content classes for route, method, media/header presence, MCP phase, completion, and response status. It never emits a URL or query, IP/network address, user-agent, header value, request or response body, JSON-RPC ID, tool name or argument, prompt, provider payload, comment text, user identifier, or credential. The optional lesson path and Gemini candidate scout share one aggregate AI budget ledger. Only four aggregate budget data values are retained in that ledger: UTC month, fixed monthly limit, charged nano-USD total, and update time. A non-content schema marker is also stored. The budget ledger contains no candidate or request content. It also contains no target, query, prompt, response, or credential. This log boundary does not change the separately disclosed storage of accepted generalized candidate fields and anonymous occurrence metadata in a private GitHub issue, or the aggregate budget ledger. Infrastructure providers may retain operational metadata such as time, route, status, latency, IP/network data, and security signals for their configured security and operations periods under their own policies, which AskRigor does not control.

Data sharing and connected clients

Research results are returned to the connected client that invoked the request. OpenAI, GitHub, ChatGPT, and infrastructure providers process data within their respective service boundaries. Google Gemini and Google Search process the screened automated-scout request described above; when strict validation requires it, Google Gemini alone also processes the bounded no-search correction payload. Research providers process necessary queries or identifiers. Their retention is governed by their respective policies; AskRigor does not control it.

Security and minimization

Research operations are read-only and send only information needed for the requested provider lookup. The automated Gemini scout rejects non-de-identified targets before provider access, uses a fixed model and compact fixed-column output, reconstructs and checks the unchanged strict server contract, reconciles the actual Google Search queries, permits at most one no-search correction, and is limited by one per-scout reservation and a shared monthly budget. The lesson path is separately consented, strictly screened, and limited to a private review write. AskRigor does not return provider credentials, raw Gemini output, hidden model reasoning, or search-result HTML, and it does not execute provider content as instructions.

Choices and deletion

You may choose not to make a research request and may decline lesson submission without losing the research response. You may request access, correction, or deletion of personal data AskRigor controls. To request earlier deletion of an optional lesson candidate, send its private-safe ARL-#### receipt to joel@askrigor.com. AskRigor cannot fulfill requests for provider or connected-client data it does not control. Please avoid sending credentials or unnecessary sensitive material by email.
