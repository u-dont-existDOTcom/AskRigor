Privacy Notice

Scope

This notice describes AskRigor’s v0 read-only retrieval service and the public data it processes to answer a connected client’s request.

Information processed

During an active request, the service processes supplied queries and identifiers, provider responses, normalized source metadata, pagination and access information, and structured errors needed for retrieval and provenance.

Public YouTube data

When a connected client requests it, AskRigor processes API-visible public YouTube author/channel IDs, optional display names, comment and reply text, comment and reply IDs, timestamps, and counts. These data can be personal data even when public. The service does not claim access to private, deleted, moderated, hidden, held-for-review, unavailable, or never-posted material.

Why and where data is processed

AskRigor sends the query or identifier necessary for a request to public-data providers: NCBI/PubMed, Europe PMC, ClinicalTrials.gov, Crossref, and YouTube Data API v3. Providers process requests under their own policies.

Storage and retention

AskRigor uses request data and returned data only for the active request and does not persist user accounts, search history, retrieved records, public comments, replies, or credentials in v0. It has no database, file store, profile, queue, or transcript store for this service.

Operational metadata

The AskRigor application does not persist operational metadata and does not log raw MCP request/response bodies or credentials. Infrastructure providers may retain time, route, status, latency, IP/network data, and security signals for their configured security and operations periods under their own policies; AskRigor does not control those provider retention periods.

Data sharing and connected clients

Results are returned to the connected client that invoked the request. Provider and connected-client retention is controlled by their own terms; AskRigor does not control that retention.

Security and minimization

AskRigor is read-only and sends only information needed for the requested provider lookup. It does not return provider credentials and does not execute provider content as instructions.

Your choices and requests

You may choose not to submit a request. You may contact us to request access, correction, or deletion of personal data AskRigor controls; requests are handled as required by applicable law. AskRigor cannot fulfill requests for provider or connected-client data it does not control. Please avoid sending credentials or unnecessary sensitive material by email.

Changes

We may update this notice to reflect changes to the service or its processing. The effective date above identifies the current version.

Contact

For privacy questions or requests, contact joel@askrigor.com.
