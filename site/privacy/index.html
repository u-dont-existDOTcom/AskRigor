Privacy Notice

Scope

This notice describes AskRigor’s v0 research retrieval path and its separately configured, optional lesson-feedback path. Research operations remain read-only and do not modify provider records. The short-lived Custom GPT YouTube continuation described below is the only research state retained across application requests.

Connected research transports

The public MCP service and Custom GPT Actions use the same transient research retrieval path and shared abuse limits. The research Action transport is independently gated by ASKRIGOR_RESEARCH_ACTIONS_ENABLED, limits each serialized response to 60,000 UTF-8 bytes, and returns no more than 48,000 UTF-8 bytes of exact protocol text per ordered chunk. Requests may contain user search terms and public identifiers; responses may contain public provider metadata and comment text. The application does not log full request or response bodies or write them to durable storage. Infrastructure, connected clients, and research providers may process operational or request data under their separately controlled policies. This does not change the separately consented lesson-feedback path described below.

Information processed

During an active request, the service processes supplied queries and identifiers, provider responses, normalized source metadata, pagination and access information, and structured errors needed for retrieval and provenance.

Public YouTube data

When a connected client requests it, AskRigor processes API-visible public YouTube author/channel IDs, optional display names, comment and reply text, comment and reply IDs, timestamps, and counts. These data can be personal data even when public. The service does not claim access to private, deleted, moderated, hidden, held-for-review, unavailable, or never-posted material.

Why and where data is processed

AskRigor sends the query or identifier necessary for a request to public-data providers: NCBI/PubMed, Europe PMC, ClinicalTrials.gov, Crossref, and YouTube Data API v3. Providers process requests under their own policies.

Optional lesson feedback

After AskRigor rechecks a concrete criticism, it may display a generalized lesson and ask for separate consent to submit it. This optional, consequential Action sends AskRigor only generalized structured fields, not the raw chat, and creates a private review candidate. It is not automatic learning and cannot change AskRigor without human review.

Screening and recipients

AskRigor applies deterministic screening and a fixed OpenAI privacy check before GitHub, then screens the result again. OpenAI receives only the already generalized candidate fields. If every check passes, GitHub receives the accepted lesson fields, a privacy marker, and anonymous occurrence metadata for private review. ChatGPT handles the surrounding conversation under its own settings and terms.

Storage and retention

Direct MCP continuation remains client-carried and stateless. For Custom GPT YouTube continuation only, AskRigor keeps the existing signed, minimized continuation token in process memory behind a short unguessable handle for no longer than one hour. The token contains a video identifier, provider cursor, counters, bounded comment and reply identifiers, and a rolling digest; it contains no comment or reply text, author identity, provider credential, or protocol text. This memory map is limited to 2,048 handles and 16 MiB. It is never written to disk or application logs. Server restart, expiry, or capacity eviction invalidates a handle and requires the audit to restart from the video identifier. This process-local design runs on a single application replica and must not be horizontally scaled unless approved sticky routing or shared state preserves every continuation chain. Apart from this bounded in-memory exception, AskRigor does not persist user accounts, search history, retrieved records, public comments, replies, or credentials. For optional lesson feedback, the private review candidate stores the accepted generalized fields, an anonymous occurrence count, first/last seen times, and a deduplication marker. No user account, conversation ID, medical history, upload, or raw quotation is intentionally stored. Rejected or incorporated candidates become deletion-eligible only after more than 90 complete days from terminal review. Deletion is not automatic; a maintainer must act, so it may occur later.

Operational metadata

The application does not emit or store request-body logs, response-body logs, candidate-content logs, or a dedicated application access log. The optional lesson path uses an aggregate privacy-check budget ledger. Only four aggregate budget data values are retained in that ledger: UTC month, fixed monthly limit, charged nano-USD total, and update time. A non-content schema marker is also stored. The budget ledger contains no candidate or request content. This log boundary does not change the separately disclosed storage of accepted generalized candidate fields and anonymous occurrence metadata in a private GitHub issue, or the aggregate budget ledger. Infrastructure providers may retain operational metadata such as time, route, status, latency, IP/network data, and security signals for their configured security and operations periods under their own policies, which AskRigor does not control.

Data sharing and connected clients

Research results are returned to the connected client that invoked the request. OpenAI, GitHub, ChatGPT, and infrastructure providers process data within their respective service boundaries, and research providers process necessary queries or identifiers. Their retention is governed by their respective policies; AskRigor does not control it.

Security and minimization

Research operations are read-only and send only information needed for the requested provider lookup. The lesson path is separately consented, strictly screened, and limited to a private review write. AskRigor does not return provider credentials and does not execute provider content as instructions.

Choices and deletion

You may choose not to make a research request and may decline lesson submission without losing the research response. You may request access, correction, or deletion of personal data AskRigor controls. To request earlier deletion of an optional lesson candidate, send its private-safe ARL-#### receipt to joel@askrigor.com. AskRigor cannot fulfill requests for provider or connected-client data it does not control. Please avoid sending credentials or unnecessary sensitive material by email.

Changes

We may update this notice to reflect changes to the service or its processing. The effective date above identifies the current version.

Contact

For privacy questions or requests, contact joel@askrigor.com.
