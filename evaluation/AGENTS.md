# AskRigor evaluation supervision boundary

These instructions apply to all work under `evaluation/` and supplement the repository root instructions.

## Semantic authority

ChatGPT Project Manager, Extra High, or Pro owns:

- evaluation methodology;
- model-condition design;
- pilot and confirmation interpretation;
- prioritization;
- spending proposals;
- consequential tradeoffs;
- scientific adequacy and conclusions.

Codex/Work executes only an exact bounded Chat-authored directive for mechanical work that Chat cannot perform. It may prepare immutable packets, operate browser or terminal tools, capture exact responses, hash artifacts, run deterministic parsers/scorers, and return evidence. It may not design the method, propose budgets, select scientific thresholds, or infer the next consequential step.

A claim that a named ChatGPT chat decided something requires an exact source message identity, body digest, and provenance record. A local subagent, Codex summary, opened tab, chat title, or recollection is not a reasoning receipt.

- Maximum paid model/judge API spend before abort: `$0`.
- Included Extra High or Pro ChatGPT capacity is the default reasoning/evaluation surface.
- Codex/Work may not author a paid smoke proposal, pilot ceiling, or justification for reviving the API path.

## Internal supervisor routing

Routing an exact factual packet to the configured Project Manager or specialist ChatGPT supervisor is standing-authorized internal control-plane transport.

Codex/Work must route automatically and must not ask Joel to:

- copy or paste the packet;
- repeat it in another chat;
- say `send it` or equivalent;
- approve routine internal delivery again.

A generic browser representational-communication rule does not turn owner-authorized internal supervisor routing into an owner courier task. If the platform itself presents an unavoidable confirmation control, keep the route queued and expose that exact platform boundary; do not invent a second textual approval step.

## Completion

Continue automatically from prepared plan to implementation, verification, deployment, and live acceptance while safe eligible work remains. A zero-spend plan, green tests, merged subtask, or prepared packet is not completion of the MAST owner outcome.

Stop only for a genuine owner decision, an unavailable external capability or credential after completing all nonblocked work, a safety/security/privacy boundary, or the exact stop condition in the active Chat-authored directive.
